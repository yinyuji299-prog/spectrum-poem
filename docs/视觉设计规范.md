# 《频谱之诗》视觉设计规范（v4 · 学术出版物语言）

> **用途**：新增页面 / 组件前先读这份文件，避免重新引入"AI 味"。
> **适用**：全站 8 个页面 + Canvas / SVG 图形。

---

## 一、为什么重做：v3 的"AI 感"从哪来

v3 的界面问题不在内容，而在**视觉语言**——它命中了 AI 生成页面的全部特征。
逐条拆解（**这些是禁止项，不要再引入**）：

| # | 症状 | 具体表现 | 为什么显得"AI" |
|---|---|---|---|
| 1 | **Tailwind 默认调色板** | `#2563EB` `#8B5CF6` `#F59E0B` `#10B981` `#E11D48` | 这五个色值是 Tailwind 出厂配置，是 AI 生成页面最强的指纹 |
| 2 | **五色语义体系** | 每个标签换一种颜色（蓝/紫/琥珀/绿/玫红） | 像调色板 demo，色彩在"装饰"而非"表意" |
| 3 | **柔和多层阴影 + hover 抬升** | `box-shadow: 0 2px 4px …, 0 6px 16px -6px …` + `translateY(-4px)` | AI 的"高级感"公式，真实出版物不用投影 |
| 4 | **毛玻璃顶栏** | `backdrop-filter: saturate(1.6) blur(14px)` | 2021 年后 AI 模板的标志性装饰 |
| 5 | **Emoji 当图标** | 🎨🔑🎡🩺🗜️🦋🌀… | 排版失控的默认退路 |
| 6 | **胶囊标签 + 荧光笔高亮** | `border-radius:999px` + `linear-gradient` 下划线 | 胶囊满屏飞是模板感的核心 |
| 7 | **同一套皮肤** | 8 种组件全是「圆角 + 描边 + 阴影」 | 缺少层级差异，读起来没有节奏 |

**根因**：把"漂亮"理解成了"加装饰"。真正的刊物感来自**克制**。

## 二、v4 设计原则（五条）

1. **纸与墨。** 少色、深色、无荧光。**色彩只承担语义，不承担装饰。**
2. **发丝线为主，白底保留极轻投影例外。** 用 1px `--line` 做分隔与层级；白底卡片仅允许 `0 1px 2px rgba(17,17,17,.04)` 级别的辅助投影，不使用毛玻璃。
3. **旁注代替气泡。** `border-left: 2px` 细线 + 等宽小字标签；标签可保留小圆角，但不使用满宽胶囊。
4. **三层字体分工。** 标题衬线（刊物感）/ 正文无衬线（中文小字清晰）/ 数字等宽。
5. **小圆角服务于可读层级。** 普通卡片使用 14px 圆角，状态标签可使用紧凑圆角；不做大面积胶囊化。

## 四、组件规范

### 栏目名 `.eyebrow`（替代胶囊徽标）
等宽小字 + `.22em` 字距 + 大写下划线，右侧用 `::after` 拉一条延伸细线：
```css
.eyebrow { display:flex; align-items:center; gap:14px;
  font-family:var(--mono); font-size:10.5px; font-weight:600;
  letter-spacing:.22em; text-transform:uppercase; color:var(--fg-4); }
.eyebrow::after { content:''; flex:1; height:1px; background:var(--line); }
```

### 旁注 —— 两种，靠左边线颜色区分
```html
<!-- 打个比方（赭色线） -->
<div class="analogy">
  <div class="ai">打个比方</div>
  <div class="at">……</div>
</div>

<!-- 想一想（蓝色线） -->
<div class="ask">
  <p class="qt"><span class="ql">先猜一猜</span>把基频调高八度，柱子会怎么动？</p>
  <p class="qd">……</p>
</div>
```
`.ai` / `.ql` 是**排印标签**（等宽 10px、`.22em` 字距、大写），**不是 emoji**。
标签词表：`打个比方` `补个概念` `换个比方` `关键一步` `接着上一章` `补充一点` /
`先猜一猜` `怎么玩` `想一想` `多问一层` `补个概念` `先问一句` `别慌`

### 标签 `.tag`
方形（`--r-sm`）、等宽 10px、`.16em` 字距、**透明底 + 细描边**。可用的修饰类：
`无修饰`（灰）/ `.blue` / `.amber` / `.green` / `.violet`

### 任务条 `.quest`
仅左侧 3px 主题色竖线 + 发丝描边；状态用**下划线小字**（`✓ 已完成`），不用胶囊。

### 徽章 `.badge`
用 `.grid.gap-0` 组成**发丝线清单**（每项 `border-bottom`），不再是卡片格。
未点亮：灰圆 `○` + 灰字；点亮：绿底圆 + 正文色字。

### 图表容器 `.stage`
白底 + 发丝描边 + `3px` 圆角。**不加阴影**。装饰性扫描线已全局禁用
（`.scanline { display:none !important }`）。

## 四·补、数据的呈现：不要"卖点卡"，要"表"

> 这是 v4.1 的教训。用户指着首页"三个关键点 / 完成度一览"说**"这里 AI 化太严重"**。

### 问题在哪

那一块原本是**三个彩色大数字 + 三行说明**，下方再来**四个彩色数字卡**。症状：

```html
<!-- ❌ AI 落地页的"卖点罗列" -->
<div class="grid grid-3">
  <div class="val"><h3 style="color:var(--rose)">O(N²) → O(N log N)</h3><p>快约 200 倍。</p></div>
  <div class="val"><h3 style="color:var(--blue)">log₂N 级</h3><p>8 点只需 3 级。</p></div>
  <div class="val"><h3 style="color:var(--violet)">零依赖</h3><p>离线即用。</p></div>
</div>
```

三条独立的病灶：

1. **每个数字换一种颜色** —— 颜色在"装饰"，不是在"表意"。
   `O(N²)`、`log₂N`、`零依赖` 三者之间没有任何需要靠颜色区分的关系。
2. **大字号数字 = 营销排版** —— 这是产品落地页的"三栏卖点"模板，
   不是科普作品该有的语言。
3. **信息被拆成"金句"** —— `快约 200 倍` 这种概括句，读者无法验证。
   一个科普作品应该给**可复算的数据**，而不是宣传语。

### 怎么改

**数字要用表说，不要用卡片说。**

```html
<!-- ✅ 刊物语言：可复算的数据对照表 -->
<table class="data">
  <thead><tr><th>信号长度 N</th><th>DFT 复数乘法</th><th>FFT 复数乘法</th><th>加速比</th></tr></thead>
  <tbody>
    <tr><td>64</td>  <td>4,096</td>      <td>192</td>    <td>21×</td></tr>
    <tr><td>1024</td><td>1,048,576</td>  <td>5,120</td>  <td>205×</td></tr>
    <tr><td>4096</td><td>16,777,216</td> <td>24,576</td> <td>683×</td></tr>
  </tbody>
</table>
```

**规格用键值表说，不要用四宫格说。**

```html
<!-- ✅ 文档语言：等宽小字标签 + 发丝线 -->
<table class="spec">
  <tbody>
    <tr><td>章节</td><td>5 章 + 1 个延伸实验，共 13 个可动手的互动任务</td></tr>
    <tr><td>依赖</td><td>零 —— 无 CDN、无外部字体、无任何接口调用</td></tr>
    <tr><td>验证</td><td>…归一化偏差 <span class="mono">6.7 × 10⁻¹⁵</span>…</td></tr>
  </tbody>
</table>
```

### 两条硬规则

1. **标题不靠颜色区分。** 全站 `<h1>–<h4>` 一律用墨色。唯一的例外是
   **同一屏内成对出现的语义对比**——如第 2 章 `DFT 4096 / FFT 192` 两个数字，
   墨色 vs 主题色，因为这里颜色**确实在传达"慢 / 快"**。除此之外，标题零彩色。
2. **能列成表就不要列成卡。** 判断方法：如果这些项目有**共同的属性**
   （不同 N 的运算量、不同字段的规格），那就是一张表；
   只有当它们彼此独立、无共同维度时，才考虑并列区块。

## 六、验证脚本

```python
# CSS 变量完整性：引用必须已定义
import io, re, glob
css = io.open('shumei-2026/assets/css/main.css', encoding='utf-8').read()
defined = set(re.findall(r'^\s*(--[\w-]+)\s*:', css, re.M))
used = set()
for p in glob.glob('shumei-2026/*.html') + glob.glob('shumei-2026/assets/css/*.css'):
    used |= set(re.findall(r'var\((--[\w-]+)', io.open(p, encoding='utf-8').read()))
print('缺失:', sorted(used - defined) or '无')
```

## 附：响应式尺寸阶梯（v5.7 新增）

作品最初按 1100px 容器 + 小字号 + 矮画布调校，在 1440p / 4K 屏上会显得
"又挤又小"（读者反馈像手机版放大）。现改为随视口分级放大。

### 缩放系数（`site.js` 的 `U()`）

| 视口宽度 | 系数 | 说明 |
|---|---|---|
| < 1024px | 1.00 | 手机 / 窄屏，保持原有紧凑手感 |
| ≥ 1024px | 1.04 | 小笔记本 |
| ≥ 1280px | 1.10 | 常规桌面（最常见） |
| ≥ 1500px | 1.18 | 2K 屏 |
| ≥ 1800px | 1.26 | 2K 宽屏 |
| ≥ 2200px | 1.34 | 4K 屏 |

系数统一作用于：**画布高度、绘图区内边距、图内字号、线宽与圆点半径**。
文字排版（CSS）另行处理，两者互不干扰。

### 排版变化

| 项目 | 原值 | 现值 |
|---|---|---|
| 正文 | 16.5px | 17.5px |
| 小字 `.small` | 14px | 15.5px |
| 导语 `.lede` | 18.5px | 20.5px |
| 章节标题 h2 | clamp(25,3vw,35) | clamp(28,3.4vw,42) |
| 容器 `.wrap` | 1100px | 1280px（≥1600px 时 1400px） |
| 区块间距 | 74px | 88px |
| 栏目名 `.eyebrow` | 10.5px | 12px |
| 标签 `.tag` | 10px | 11.5px |
| 任务文字 | 14.5px | 16px |
| 表格 | 14px | 15.5px |
| 滑块把手 | 15px | 19px（更易抓取） |

### 画布高度（随系数放大）

| 画布 | 原高 | 1440px 屏 | 2560px 屏 |
|---|---|---|---|
| 第 3 章蝶形（波形/频谱） | 158px | 174px | 212px |
| 第 1 章实验 | 236px | 260px | 316px |
| 音高实验室频谱 | 220px | 242px | 295px |
| 上传音频波形/频谱 | 160px | 176px | 214px |

CSS 侧对画布高度同时使用 `clamp()`，避免 JS 渲染前的初始高度偏小。

### 断点调整

原断点 880 / 760 / 580px 与旧容器宽度绑定，现改为 1080 / 820 / 640px，
保证在新的 1280px 容器下多栏网格与顶栏导航的切换时机正确。
